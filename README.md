# dsh-workbench

个人工作管理插件（DSH bundle）。已安装在当前 profile，通过 `link: D:\dsh-workbench` 加载。

## 目录

| 文件 | 作用 |
|---|---|
| `package.json` | bundle 清单：`dsh.bundle.patch` + `dsh.client`，含 `exports` / `files` 白名单 |
| `cordis.patch.yml` | 插入 `workbench` 插件行 |
| `index.js` | Host 半：数据持久化 + `/workbench/api` + 日/周/月报渲染 |
| `client.js` | 前端：侧边栏图标 + 整页（今日 / 计划 / 统计 / 报告） |
| `locale/zh.json`、`locale/en.json` | 插件显示名与描述 |
| `icon.svg` | 插件图标 |

## 数据在哪

- 数据文件：`C:\Users\me\.dsh\profiles\desktop\worklog\workbench.json`
- 导出目录：页面「设置」可改，当前 `D:\workplace\worklog`
  导出结构：`<root>/YYYY/MM/<日期>.daily.md`、`<root>/YYYY/<周>.weekly.md`、`<root>/YYYY/MM/<月>.monthly.md`

## 改完代码怎么生效

1. 改这个目录里的文件
2. 侧边栏 → 插件 → 「工作台」这一行**关闭再打开**（重载 Host 模块）
3. **刷新浏览器/面板**，前端 bundle 才会换成新的

只改 `index.js` 时第 2 步即可；改了 `client.js` 必须再做第 3 步。

## 已实现

**M1**
- 日任务 6 字段表单 + 折叠高级项（议题号 / 截止日 / 状态 / 实际工时）
- 周条目、`+ 子任务`、未归拢收件箱、顺延未完成
- 统计：计划达成率 / 计划外占比 / 估算偏差 + 近 8 周 + 项目分布

**M2**
- 月条目与**本月目标**（KR：指标 + 目标值 + 当前值 + 单位）
- 报告视图：日报 / 周报 / 月报，任意周期切换、预览、复制、导出
- 日报字段映射预览（今日完成工作 / 所用工时 / 未完成工作和明天计划 / 日志接收人员）
- 导出按 日/周/月 分目录留档

**M3**
- 插件配置页（插件 → 工作台 → 配置）：GitLab 地址 + PAT + 测试连接 + 项目勾选
- 令牌类型诊断：账号形如 `project_*_bot` 会提示"项目令牌可能无法跨项目"
- 任务表单高级区：选项目、填议题号关联，或直接「建 issue」回填
- 错误信息按 401/403/404 给出可操作原因

**M4（提交链路）**
- 配置页「钉钉日志」区：检测 `dws` 登录态、选模板、字段映射、搜索并选接收人
- 报告页日报的「提交钉钉」：先 dry-run 预览将要提交的内容，再确认提交
- 提交成功后把 reportId 与钉钉跳转链接写入 `reports` 与 `runs`
- 字段规则按本机 `dws` 契约实现：`type=1 → markdown`，其余 `→ origin`；`--contents-file` 必须位于工作目录内

**M5（GitLab 任务同步）**
- 只有**日任务**关联 GitLab；周/月条目不再出现 GitLab 区
- 二级筛选：先选项目，再选该项目的里程碑（合并展示所有已勾选项目的活跃里程碑）
- 任务表单主区域（不再藏在"更多"里）：「保存」只存本地；「保存并同步 GitLab」新建或更新
- 同步内容：标题、描述、里程碑、预估工时（`time_estimate`）、实际工时（先 `reset_spent_time` 再 `add_spent_time`，避免重复累加）
- 实例不支持 `issue_type=task` 时自动降级为普通议题，并提示
- 计划视图回看不限，只限制未来（周 +1 / 月 +1）；报告视图只能回看，不越过当前周期

**M6（定时草稿 + 去掉目标）**
- 移除"月目标"模型；周报/月报的「一、目标推进」改为报告页右侧**手写文本框**，按周期保存到 `narratives`
- 定时生成草稿：默认 18:00，设置里分「周一至周四」「周五」两个时间点，周五可选同时生成周报
- 到点生成草稿 + 工作台顶部提示（去查看 / 忽略），**不会自动发钉钉**
- 软件开着才执行；开机后补当天一次；设置里有「保存并立即试跑」

**M7（汇总与归档）**
- 计划条目显示子任务汇总：`3/5 · 实 4h / 估 6h`，并显示 `延 N 天` / `提前 N 天`
- 报告页「历史」：按周期列出已生成/已提交的报告，点击直接跳转
- 设置里移除废弃的"日报默认接收人"（改用钉钉接收人）

## 已知限制

- 同步是**单向**的（工作台 → GitLab）。GitLab 侧的评论不会自动拉回
- 一条本地任务只对应一个 GitLab 任务；多条任务挂同一个 issue 会导致工时不准确
- 月报/周报不进钉钉（公司只配了日报模板）
- 报告没有历史版本；导出文件即归档
- **GitLab 令牌以明文存在数据文件里**（`workbench.json`），单机自用可以，共享机器不行
- 钉钉依赖 WorkBuddy 自带的 `dws`（`…\cli-connector-packages`），若 WorkBuddy 升级改了路径，需要在配置里填 `dwsPath`
- 未做多设备同步；备份 = 拷 `workbench.json` + 导出目录

# dsh-workbench · 个人工作台

给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 用的个人工作管理插件：记日任务、排周/月计划、实时统计、生成日报周报月报，并把任务同步到 GitLab、把日报提交到钉钉日志。

全部数据存在本机，不依赖任何云服务；对接 GitLab / 钉钉是可选能力。

```
┌ 工作台 ─────────────────────────────────────────────┐
│ [今日] [计划] [统计] [报告]                    ● 设置 │
├──────────────────────────────────┬──────────────────┤
│ 还剩 2 件事  预计还需 3.5h          │  ╭───╮ 今日完成   │
│ ▸ 人力报表国资委口径                 │  │67%│ 2 / 3    │
│   ☑ 验证PM02表取数      中 3h 实 4h│  ╰───╯ 计划外 1  │
│   ☐ 完成媒劳2表         高 2h     │  预估 5h  实际 4h │
│ ▸ 计划外                           │  本周进度 ▓▓▓░░  │
└──────────────────────────────────┴──────────────────┘
```

## 功能

### 今日
- 按计划条目分组的任务列表，勾选即完成，行内直接改状态
- 顶部一句话状态："还剩 2 件事 · 预计还需 3.5h"
- 右侧指标栏：完成环、预估/实际工时、本周进度、近 7 天趋势
- 顺延未完成（带确认）、导出当日日报

### 计划
- 周 / 月两档，可无限回看，未来只允许推一格
- 周条目可拆子任务；未被归拢的日任务进"未归拢收件箱"，一键归入
- 每个条目显示子任务汇总（`3/5 · 实 4h / 估 6h`）与延期天数

### 统计
- 本周 / 本月切换（本月按天）
- **任务构成**：环形图，计划内完成 / 计划外完成 / 未完成
- **完成与工时趋势**：双折线，悬停看单点
- **累计完成与理想进度**：实际 vs 理想节奏，直接告诉你落后几条
- **计划条目分布**：按计划条目的完成数，条目多了卡片内滚动
- 全部可点击下钻到任务清单；周末/节假日按可维护的节假日表判定加班

### 报告
- 日报 / 周报 / 月报，单页文档式布局
- **所见即所得**：只有「未完成工作和明天计划」和「目标推进小结」可编辑（无边框、失焦自动保存），其余（完成项、工时、统计）自动生成不可改
- **恢复默认**：一键回到自动生成的内容
- **AI 生成**：调用 DSH 已配置的模型生成小结，先预览再决定是否替换
- 导出 Markdown / **Word（.docx）**
- 日报可一键提交到钉钉日志，提交前 dry-run 预览，提交记录留痕（含 reportId 与钉钉链接）

### 集成（可选）
- **GitLab**：日任务可关联项目 + 里程碑，一键建 Task/议题、同步标题/描述/工时、把备注作为评论推送；只有日任务能关联，周/月条目不行
- **钉钉**：通过本机 `dws` 提交公司日志，字段映射按模板自动生成，接收人必填
- **定时**：工作日 / 周五分别设置生成草稿的时间，到点在页面提示，不自动外发

## 安装

前置：已安装 DSH（桌面版或 `dsh web`）。

### 方式 A：本地目录

```powershell
git clone https://github.com/<你>/dsh-workbench.git D:\dsh-workbench
```

打开 DSH → 侧边栏「插件」→ **Add plugin** → 填绝对路径 `D:\dsh-workbench` → 安装。

### 方式 B：Git 固定 commit

```
git+https://github.com/<你>/dsh-workbench.git#<40位commit>&path:/
```

安装后在侧边栏底部出现「工作台」图标。

## 配置

侧边栏「插件」→ **工作台** → 行内 **配置**：

**GitLab**（可选）
1. 实例地址（`http://host:port` 或 `.../api/v4` 都行）
2. 个人访问令牌（scope `read_api`；要建任务/发评论需要 `api`）
3. 测试连接 → 勾选项目 → 保存

**钉钉**（可选）
1. 需要本机有 `dws` 命令行并已登录（`dws auth login`）
2. 选日志模板 → 自动拉字段 → 保持默认映射
3. 搜索并添加日志接收人（至少一个）

**设置**（工作台右上角）
- 导出根目录、定时生成时间、节假日/调休表

## 数据

默认存在 DSH profile 目录下：

```
<profile>/worklog/workbench.json        全部数据（JSON）
<导出根目录>/YYYY/MM/<日期>.daily.md    报告归档
```

备份 = 拷这两处。**GitLab 令牌以明文存在 `workbench.json` 里**，别在共享机器上使用。

## 开发

```powershell
# 改完代码后在「插件」页把工作台一行关闭再打开（重载 Host 模块）
# 改了 client.js 还需刷新页面
```

目录结构：

| 文件 | 作用 |
|---|---|
| `package.json` | bundle 清单：`dsh.bundle.patch` + `dsh.client` |
| `cordis.patch.yml` | 插入 `workbench` 插件行 |
| `index.js` | Host 半：数据持久化、HTTP 接口、报告渲染、GitLab/钉钉/Word 导出 |
| `client.js` | 前端：侧边栏图标 + 四个页面 |
| `locale/*.json` | 插件显示名与描述 |
| `diagnose-gitlab.ps1` | GitLab 连通性诊断脚本 |

技术要点：
- 后端零依赖，只用 `node:fs` / `node:child_process` / 全局 `fetch`
- 图表全部手写 SVG，不引入图表库
- Word 导出自行拼装 OOXML + ZIP（store 模式），无第三方库

## 已知限制

- 定时生成只在软件运行时执行，关机不跑（开机后补当天一次）
- GitLab 同步是单向的（工作台 → GitLab）
- 一条本地任务只对应一个 GitLab 任务
- 报告没有版本历史，导出文件即归档
- 节假日表需手动维护（不内置国务院放假安排）
